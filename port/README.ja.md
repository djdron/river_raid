# River Raid の C++ 移植

[English](README.md) | [Русский](README.ru.md) | [Українська](README.uk.md) | [Deutsch](README.de.md) | [Polski](README.pl.md) | [Italiano](README.it.md) | [Español](README.es.md) | [中文](README.zh.md) | 日本語

教育目的の非公式なファンプロジェクトで、Activision や Microsoft とは無関係です。ゲームのいかなる部分も含まれていません（`../README.ja.md` の免責事項を参照）。

ゲーム全体：`river_raid` はオリジナルと同じように River Raid を動かします。デモモード、ゲームの選択、1 人と 2 人プレイ、飛行機、燃料、敵、橋、得点、残機、ハイスコア、一時停止、サウンドです。川の生成器とゲームロジックはオリジナルと同じ RAM の状態をフレームごとに作り、描画は同じ画面を作ります（「検証」を参照）。

## ビルド
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```
コアとツールに必要なのは C++17 コンパイラだけです。ゲーム `river_raid` とビューア `river_view` には SDL3 が必要です。CMake はインストール済みの SDL3（3.4 以降）が見つかればそれを使い、なければ構成時に GitHub から SDL 3.4.20 をダウンロードして（git とインターネットが必要）静的にリンクします。Linux で SDL をソースからビルドするには X11/Wayland の開発パッケージが必要です（SDL の `docs/README-linux.md` を参照）。そうしたパッケージがないと SDL 3.4 はエラーで止まり、それなしでビルドするオプション（たとえば `-DSDL_X11_XCURSOR=OFF`）を示します。SDL をまったく使わない場合：`cmake -S . -B build -DRR_VIEWER=OFF`。

SDL3 の代わりに SDL2 を使う場合（Xbox の UWP など、SDL3 がもうサポートしないプラットフォーム向け）：`cmake -S . -B build -DRR_SDL2=ON`。このとき CMake はインストール済みの SDL2（2.0.18 以降）を使うか、SDL 2.32.10 をダウンロードします。プログラムは `sdl/host.h` を通してだけ SDL とやりとりし、これはバージョンごとに 1 回ずつ実装されています。どちらでも同じ画面になります。

Windows の Visual Studio では：`cmake --build build --config Release`。プログラムは `build\Release\` にできます。Windows（MSVC）、macOS（Xcode、Apple M2）、Linux（gcc）でビルドして遊べることを確認済みです。

## ゲーム
```
river_raid [rom] [オプション]
```
引数がなければ自分で ROM を見つけ（`rom` を参照）、カートリッジと同じように始まります。デモモード、そして START です。

| オプション | 働き |
|---|---|
| `rom` | カートリッジのイメージ（8192 バイト）。標準では `rom/River_Raid.rom` を現在のフォルダと 3 つ上までのフォルダで探すので、リポジトリからでも `port/build/Release` からでも引数なしで起動できます |
| `-os ファイル` | Atari 自身の OS の文字と数字：OS ROM のイメージ（10 KB または 16 KB）か 1 KB のフォント。指定しなければ内蔵の AltirraOS のフォントを使います |
| `-seed N` | 別の川。敵や補給所も別になります。N は川の生成器が始まる状態で、1〜16777215。ゲーム 1 はその川の始まりから、ゲーム 3–8 はその川の橋 5、20、50 から始まります。各ゲームはいつものレベルを保つので、難しさはいつもどおり上がります。カートリッジ自身の川は `-seed 16241891` です |
| `-bridge N` | すべてのゲーム（1–8）が橋 N（1〜9999）から始まります。橋のカウンターは N、レベルはその橋のレベルです（80 以降はオリジナルと同じく 79/80 を交互に）。`-seed` と一緒にも使えます。スタート地点は川の生成器をそこまで走らせて求めます（9999 でも 1 秒かかりません） |
| `-random N` | POKEY の RANDOM カウンターの初期値。どの敵がいつ目覚めるかと、爆発のノイズを決めます。標準では時計から取ります。実機の値が電源を入れた瞬間で決まるのと同じで、毎回違う実行になります。同じ N と同じ入力なら、実行は正確に繰り返されます |
| `-pal` | PAL 機として遊ぶ：実際の PAL の Atari と同じく、燃料補給所はレベル 46 ではなく 47 まで減り続けます。PAL の色。画面のタイミングは NTSC のままです（「まだできていないこと」を参照） |
| `-colours ntsc\|pal` | NTSC 機または PAL 機の色。標準は PAL。プレイ中に C で切り替え |
| `-palette altirra\|atari800` | 色のモデル：`altirra`（標準）または `atari800`（中間の明るさがより暗い）。プレイ中に V で切り替え |
| `-border` | エミュレータのように、黒い枠を含むフレーム全体（384×240 から両側 10 列ずつ除いたもの）を表示します。標準ではウィンドウは流れる文字全体を含むゲームの画面 364×200 だけを表示するので、全画面では約 20% 大きく見え、ウィンドウはその分低くなります。プレイ中に O で切り替え |
| `-filter sharp\|nearest\|linear` | 画面をウィンドウやスクリーンにどう拡大するか：`sharp`（標準）はくっきりしたピクセルで整数倍に拡大してから、最終的な大きさまでなめらかに拡大するので、くっきりしたまま、どのピクセルも同じ大きさになります。`nearest` は単純な四角ですが、整数倍でない倍率では（横方向は常にそう。Atari のピクセルは正方形でないため）一部の列が画面のピクセル 1 つ分太くなります。`linear` はなめらかでぼやけます。プレイ中に L で切り替え |
| `-stats` | レンダラーと画面のリフレッシュレートを表示し、その後 1 秒ごとにフレームレート、1 フレームの時間、サウンドのキューを表示します |
| `-nosound` | 音を出さない |

ウィンドウのタイトルに、使用中の色と拡大方法が表示されます。60 Hz（や 120 Hz…）の画面では、ゲームは画面のリフレッシュレートぴったりで動きます（Atari の 59.92 ではなく 60 フレーム/秒）。そのためどのフレームも同じ時間だけ表示されます。ほかの画面では Atari のレートで動きます。

例：`river_raid -bridge 30` は橋 30 から始まります。`river_raid -seed 12345` は別の川です。`river_raid -seed 12345 -bridge 80` はその川のいちばん難しいところです。

電源を入れると、デモモードが川の上を飛びます。START でゲームが始まります。SELECT（または OPTION）でゲーム 1–8 を選びます。偶数番号は 2 人プレイ（交代で遊ぶ）で、ゲーム 3–4、5–6、7–8 は橋 5、20、50 から始まります。Atari のキーボードのどのキーでも一時停止します。ゲームオーバーの後、デモモードがまた始まるまで（約 35 秒）画面は止まったままです。ゲームとビューアは普通の方法で終了します：ウィンドウを閉じる、Alt+F4、Cmd+Q。

| キー | Atari |
|---|---|
| 矢印キーまたは W A S D | ジョイスティック：左右で旋回、上で加速、下で減速。どの方向でも橋のところから飛行機が飛び出します |
| 左右の Ctrl、Z、X | 発射 |
| F4 または Enter | START |
| F3 | SELECT |
| F2 | OPTION |
| スペース | キーボードのキー：一時停止 |
| F、F11 または Alt+Enter | 全画面 |
| C | NTSC / PAL の色 |
| V | 色のモデル Altirra / atari800 |
| O | ゲームの画面だけ / 枠を含むフレーム全体 |
| L | 拡大方法：sharp / nearest / linear |
| Esc | 全画面を終える |
| マウスクリック | マウスが動くまでマウスポインターを隠します（全画面にしたときも同じ） |

キーボードは両方のジョイスティックを操作するので、1 人でも 2 人プレイができます。ゲームパッド：1 台目はジョイスティック 1（2 台目がない間は 2 も）、2 台目はジョイスティック 2。十字キーか左スティック、A/B/X/Y か右トリガーで発射、Start = START、Back = SELECT。

## 川のビューア
```
river_view [rom] [オプション]
```
オリジナルのデモモード、つまり誰も START を押さないときに流れる川の上の飛行を表示します。電源を入れると画面がゲーム 1 の川で埋まり、その後 1 フレームに 1 ラインずつスクロールします。船とヘリコプターが目覚めて動き、戦車は橋へ向かって撃ち、ヘリはミサイルを撃ちます（移植したゲームロジック、`src/game.cpp`）。下にはパネルと、クレジット、「Press START key」、虹色の Activision ロゴが流れる文字の行があります。オプションはゲームと同じです：`rom`、`-os`、`-seed`、`-bridge`（デモモードがその橋から飛ぶ）、`-random`、`-pal`、`-colours`、`-palette`、`-border`、`-filter`。

文字と数字 1–9 は OS のフォントから来ていて、カートリッジには入っていません。移植版には AltirraOS のフォントが内蔵されています。atari800 に同梱されている無料の代替 OS です（ライセンス：著作権表示を残せば複製と改変が可能。`src/os_font.cpp` を参照）。基準の記録もこれで作りました。`-os ファイル` は、OS ROM のイメージ（10 KB または 16 KB）か 1 KB のフォントファイルから Atari 自身の OS のフォントを読み込みます。

| キー | 動作 |
|---|---|
| スペース | 一時停止 |
| 上 / 下 | 速く / 遅く。停止を経て後ろ向きの飛行まで（どちらの向きも x1/4〜x16） |
| マウスホイール、PgUp / PgDn | 手で川をスクロール、1 画面ずつ |
| Backspace | 通常の速さで、いちばん新しいラインに戻る |
| B / Shift+B | 次 / 前の橋 |
| Home | 最初から |
| F1 / F2 / F3 | サウンドテスト：ゲームのサウンドドライバーで爆発 / 発射 / 得点の音（デモモード自体はオリジナルと同じく無音） |
| F | 全画面 |
| C | NTSC / PAL の色 |
| V | 色のモデル Altirra / atari800 |
| O | ゲームの画面だけ / 枠を含むフレーム全体 |
| L | 拡大方法：sharp / nearest / linear |
| Esc | 全画面を終える |
| マウスクリック | マウスが動くまでマウスポインターを隠します（全画面にしたときも同じ） |

オリジナルの画面との比較（デモモード、フレーム 1000–2300、オリジナルの RANDOM の値を使用）：川の領域とパネルはピクセル単位で一致し、流れる文字の行も、いちばん外側の列（24 より左、359 より右）を除いて一致します。そこではエミュレータが端での細かいスクロールを別の方法で扱っています。

どの物体がいつ目覚めるかは POKEY の RANDOM レジスタが決めます。これはハードウェアのカウンターで、読み取る瞬間はマシン全体のタイミングで決まります。移植版はこのカウンターをモデル化し（`src/pokey_random.h`）、実機が電源投入時に始めるのと同じように時計から始めます。そのため実機と同じく毎回違う実行になります。`-random N` で実行を繰り返せます。

## コード
移植版は、オリジナルの逆アセンブルが手元になくても読めるように書かれています。
- 状態のフィールド、関数、定数は意味を表す名前になっています（`planeState`、`shellTimer`、`enteringSlot`、`positionObject`、`kFacingLeft`）。各フィールドのコメントにはオリジナルの RAM アドレスが、各関数のコメントには元になったコードのアドレスが書いてあるので、逆アセンブル（`disasm/`）や記録をたどることもできます。
- カートリッジのテーブルはアドレスではなく、`src/rom.h` の名前付きアクセス関数で読みます（`rom.points(type)`、`rom.objectHeight(type)`、`rom.shellRise(t)`…）。
- オリジナルで 8 ビットのラップアラウンドになっている値は、そのまま 8 ビットで扱います（`lo()`）。位置が画面を一周するからです。オリジナルが 6502 のキャリーフラグをある足し算から次の足し算へ持ち越しているところでは、`addWithCarry`/`subtractWithBorrow` がそれを明示します。
- ディスプレイリスト割り込み（`display.cpp`）だけは命令に近いままです。走査線の中でのタイミングがどの衝突が見えるかを決めるので、サイクル数を数えながら実行します。

動作を変えないはずの変更は `tools/equivalence` で確認します。古いコミット（06ffc73 以降）を作業コピーの隣にビルドし、両方を各ゲームの川 150 000 ライン（NTSC と PAL）、電源投入からのランダムなプレイ、オリジナルの記録の 194 の状態からのランダムなプレイで動かし、1 ステップごとに状態全体、画面、サウンドレジスタを比較します。生成器、ゲーム、表示の名前変更と構成の見直しはこの方法で確認し（差分 0）、下のすべての検証も通っています。

```
port/tools/equivalence/build.sh 06ffc73
port/build/eq/eq
```

## 生成器のしくみ
`nextLine()` を呼ぶたびに、画面の一番上の新しいラインが 1 本できます。
1. `countLines`：ラインを数える（ブロックは 32 ライン、区間は 2 ブロック、橋まで 16 区間）、LFSR を 1 歩進める、区間の始まりで新しい目標の幅を決める（`chooseSectionWidth`：島が開いたり閉じたりする）。
2. `changeIsland`：島と水の幅が目標へなめらかに近づく。
3. `moveBank`：岸のランダムウォーク。範囲の端と新しい物体の手前で向きを変える（`bankWouldHitObject`）。
4. `startDecoration`：岸の家や山。
5. `drawLine`：ラインの 48 バイト（塗りつぶし、`$B800` のテーブルの縁の部品、飾りの 1 行）。
6. `scrollObjects` / `placeObject`：物体のスロットがずれ、16 ラインごとに新しい物体を置く（`chooseEnemy`、`positionObject`、`placeTank`）。

生成はプレイヤーにも `RANDOM` にも依存しません。基準実行で確認しました。POKEY のシードを変えても、ボットの実行と入力なしの飛行を比べても、どのラインでも同じ状態になります。

## 検証
- 基準の状態から：川全体の 119 758 ライン（120 000 フレーム）で、状態にもビットマップのラインにも差分 0。
- ゼロから（`startGame(1)`、エミュレータなし）：画面を埋める 165 ラインの後、状態はオリジナルと一致し、その後 29 757 ラインで差分なし。
- 橋を破壊し閃光の効果が出るボットのゲーム：差分は復活のフレームだけ。まだ移植していない再開のコードによるものです。
- 検証はわざと入れたバグを捕まえます。意図的な 4 つの破損（ランダムウォークの条件、水の幅、描画、塗りつぶしの色）は、どれも差分を生みました。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/ghost_film.txt 30001 out -ghost -ram 0:30000
port/build/terrain_check rom/River_Raid.rom out/ram.bin 0 240 29760 5 -fresh 1 145
```

描画：新しいラインが画面の 20 行目に入るすべてのフレームで、オリジナルのその行を、C++ の生成器（ゼロから開始）のラインの `drawScreenLine()` と比較します。
- 物体を生成器が置いた場所に置いた場合：29 000 フレームで 96.8% の行が同一（120 000 フレームで 95.3%）。残りは、ゲームが物体を動かした場所で異なります。
- 物体の位置を動いているゲームから取った場合（`-ram`、スロットの x、フラグ、種類）：98.1% が同一。残る行はすべて、ゲームロジックが描く道路の戦車（`$38`）が動いているあいだだけ異なります。29 600 行中、説明のつかない行は 0。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/ghost_film.txt 30001 out -ghost -strip 20 -ram 0:30000
port/build/render_check rom/River_Raid.rom out/strip.bin out/frames.csv -ram out/ram.bin
```
パネルと流れる文字の行：OS のフォントとカートリッジから作った文字セットはオリジナルの RAM と同じで、スクロールの状態（$3FB3/$26/$27）は毎フレーム一致し、描いた 180–239 行は 1299 フレームすべてで同一です。ただし流れる文字の行のいちばん外側の列は除きます（「川のビューア」を参照）。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/attract_idle.txt 2300 out -screens 1000:2299 -ram 1000:2299
port/build/status_check rom/River_Raid.rom out/screens.bin out/ram.bin
```
デモモードでのゲームのフレーム（`game_check`）：電源投入後の状態（`Game::startAttract`）から始め、オリジナルの RANDOM の値を与えると、移植版は 19 900 フレーム（橋 20 まで）を、比較したどのバイトでもオリジナルの RAM と差分なく進みます。生成器の状態、物体のスロット（位置、向き、種類、衝突のビット）、戦車、その砲弾、ヘリのミサイル、衝突の結果、プレイヤー・ミサイルのメモリ、画面上の川のラインです。そこから描いた川の領域は、比較した 1299 フレームすべてでオリジナルの画面と同じです。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/attract_idle.txt 20000 out -strip 20
port/build/game_check rom/River_Raid.rom out/ram.bin out/random.log 38 19900 -attract
```

プレイヤーのいるゲーム（入力のある実行での `game_check`）。デモモードの状態から、移植版にオリジナルの入力と RANDOM の値を与え、あとは一度も読み込み直さずに単独で動かします。毎フレーム、その RAM をオリジナルの RAM と比較します（生成器、スロット、飛行機、燃料、弾、衝突、得点、残機、両プレイヤー、ハイスコアとそのチェック用バイト、パネル、流れる文字の行、プレイヤー・ミサイルのメモリ、画面のライン）。
- 1 人プレイのボットのゲーム（`start_only.txt -bot -seed 3`、8 950 フレーム：デモモード、START、4 機、橋、墜落と再開、ゲームオーバー、再びデモモード）：比較したすべてのフレームで同一。
- SELECT と一時停止キーを使う 2 人プレイ（`two_players.txt`、フレーム 3 007 のゲームオーバーまで）：ゲームオーバーまで同一（1 フレーム、下記を参照）。
- 移植版が描いた川の領域（飛行機、弾、敵、爆発、戦車、砲弾）は、ボットのゲームの比較した 1 565 フレームすべてでオリジナルの画面と同じです。

オリジナルの結果が CPU のサイクルに左右される箇所：
- DLI（`display.cpp`）は、基準のエミュレータが走査線の時間を割り振るのと同じように、サイクルを数えて実行します。最初にプレイヤー/ミサイルとディスプレイリストの読み込み、CPU はサイクル 28 まで、次にライン全体を描き（衝突も含む）、そして画面データの読み込み、WSYNC はサイクル 106 です。これにより、衝突レジスタの読み取りがすでに現在の走査線を見ているかどうかがわかります。読み取るその走査線でだけ物体に触れた弾は、橋では数えられ（その経路はサイクル 28 の後に読む）、ほかでは数えられません。オリジナルと同じです。
- RAM のスナップショットはフレームの終わりに取ります。普通、そのときオリジナルのメインループは次のフレームを待っています（AE99–AE9E）。ゲーム開始直後、川を 1 フレーム 2 ラインずつ埋め直しているあいだは、まだ 2 本目のラインを描いていることがあります（埋め直し 1 回につき 1 フレーム）。`game_check` はそうしたフレームを別に報告して比較しません。次のフレームはまた同一になります。
- モデル化していないもの：ゲームオーバー。メインループのゲームロジックは走査線 160 で始まり、DLI や VBI（走査線 248）と CPU を分け合います。ゲームオーバーのフレームでは、ハイスコアの確認とそのチェック用バイト（sub $B261、$B298）に何千サイクルもかかるため、`sub_B21A` がフレームカウンターを $FF にするのは、そのフレームでそれより前に実行されたすべての処理のサイクル数しだいで、VBI の前、後、または（2 人プレイでは）次のフレームになります。移植版は VBI の前に行います。そのためフレームカウンターが 1 ずれることがあり、その後のデモモードが 1 フレームずれます。これを再現するには、そのフレームのメインループ全体（OS の割り込みハンドラーも含む）のサイクル数が必要です。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/start_only.txt 9000 out -bot -seed 3
port/build/game_check rom/River_Raid.rom out/ram.bin out/random.log 38 8950 -attract
```

サウンド。サウンドドライバー（VBI B2A5–B3D8、`Game::soundDriver`）を、ボットのゲームの各 VBI の開始時にオリジナルが持っていた RAM の上で動かしました（2989 フレーム、うち 2199 フレームで音あり：エンジン、燃料警告、爆発、射撃、得点、戦車の砲弾）。AUDF/AUDC の値はすべて、オリジナルが書いたものと同じです。POKEY のモデル（`src/pokey_sound.cpp`）は、同じレジスタへの書き込みに対する atari800 の音と比較しました。時間に対する音量は同じ（エンベロープの相関 0.95）、同じ高さの純音は同じ、ノイズのスペクトルの形も同じ（平滑化したスペクトルのコサイン 0.94）です。ノイズのサンプルごとの模様は異なります。ノイズのカウンターがそのときどこにいるかで決まるからです。

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/start_only.txt 3000 out -bot -wav -vbi
port/build/sound_check rom/River_Raid.rom out/vbi.bin out/pokey.log out/random.log
port/build/sound_render out/pokey.log port.wav
```

## まだできていないこと
- 電源投入そのもの（A000–A17C：デモモードより前の最初の 38 フレーム）は空の画面として描いています。`Game::powerOn` はまだ正確ではありません。
- PAL 機（`-pal`）：生成器は対応していますが、ディスプレイリストとタイミングはまだです。
- 色は、エミュレータの GTIA 出力のモデルに従っています（標準は Altirra、V で atari800。どちらも標準設定でエミュレータ自身のパレットのコードとバイト単位で照合済み。atari800 はビデオレベル 16–235 を 0–255 に引き伸ばしたもの）。実際のテレビで測ったパレットではありません。どのくらい明るく見えるかは、マシンと同じくらいテレビの設定にも左右されます。
