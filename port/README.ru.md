# C++ порт River Raid

[English](README.md) | Русский

Пока здесь генератор реки и отрисовка реки так, как её показывает игра. Генератор даёт тот же результат, что оригинал, байт в байт; отрисовка совпадает с экраном оригинала построчно (см. «Проверка»).

## Сборка
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```
Ядру и утилитам нужен только компилятор C++17. Просмотрщику `river_view` нужен SDL3: если CMake находит установленный SDL3, он берёт его, иначе при конфигурации скачивает SDL 3.2.24 с GitHub (нужны git и интернет) и линкует статически. Под Linux для сборки SDL из исходников нужны dev-пакеты X11/Wayland (см. `docs/README-linux.md` в SDL). Без просмотрщика: `cmake -S . -B build -DRR_VIEWER=OFF`.

Под Windows с Visual Studio: `cmake --build build --config Release`, программы появятся в `build\Release\`. Проверено под Linux (gcc); macOS и Windows ещё не проверялись.

## Просмотрщик реки
`river_view [rom] [-os файл] [-pal]` показывает демонстрационный режим оригинала — пролёт над рекой, который игра крутит, пока никто не нажимает START: после включения экран заполняется рекой игры 1, дальше она прокручивается на 1 строку за кадр, внизу панель состояния и бегущая строка с титрами, «Press START key» и радужным логотипом Activision. ROM ищется в `rom/River_Raid.rom` текущей папки и до трёх папок выше, так что из репозитория или из `port/build/Release` он запускается без аргументов.

Буквы и цифры 1–9 берутся из шрифта ОС, которого нет в картридже. В порт встроен шрифт AltirraOS — свободной замены ОС, которая идёт с atari800 (лицензия разрешает копирование и изменение при сохранении копирайта, см. `src/os_font.cpp`); с ней же сняты эталонные трассы. `-os файл` берёт шрифт ОС самой Atari из образа ROM ОС (10 КБ или 16 КБ) или из файла шрифта на 1 КБ.

| Клавиша | Действие |
|---|---|
| Пробел | пауза |
| Вверх / Вниз | быстрее / медленнее, через остановку до полёта назад (от x1/4 до x16 в обе стороны) |
| колесо мыши, PgUp / PgDn | прокрутка по реке вручную, на экран |
| Backspace | вернуться к самой новой строке, обычная скорость |
| B / Shift+B | следующий / предыдущий мост |
| Home | начать заново |
| F | полный экран |
| Esc | выход |

Сравнение с экранами оригинала (демо-режим, кадры 1000–2300): панель и бегущая строка совпадают попиксельно, кроме крайних столбцов бегущей строки (левее 24 и правее 359), где эмулятор по-своему обрабатывает плавную прокрутку у края; река отличается только там, где игра сдвинула объект или показывает танк на мосту (логики игры ещё нет).

## Что есть
| Файл | Что |
|---|---|
| `src/river_gen.h/.cpp` | генератор: `RiverGen::startGame(n)`, затем `nextLine(line)` — одна строка экрана за вызов |
| `src/river_draw.h/.cpp` | отрисовка строки как на экране: оттенки берега, дороги у мостов, спрайты объектов (`drawScreenLine`), цвета Atari (`atariRgb`) |
| `src/status_bar.h/.cpp` | панель состояния и бегущая строка: наборы символов, панель, шаг прокрутки, отрисовка |
| `src/os_font.h/.cpp` | шрифт ОС: встроенный AltirraOS или загрузка из ROM ОС |
| `src/river_state_io.cpp` | соответствие полей адресам RAM оригинала, загрузка и сравнение (для проверки) |
| `viewer/river_view.cpp` | просмотрщик реки (SDL3), см. ниже |
| `tools/river_map.cpp` | генерирует реку и сохраняет PNG так, как её показывает игра: `river_map <rom> <игра 1..8> <строк> out.png [-pal] [-flat]` (`-flat`: только растр, фиксированные цвета) |
| `tools/status_check.cpp` | сверка панели и бегущей строки с полными экранами оригинала (`rr_oracle -screens A:B -ram A:B`) |
| `tools/render_check.cpp` | сверка отрисовки с экраном оригинала (`oracle/rr_oracle -ghost -strip 20`) |
| `tools/terrain_check.cpp` | сверка с трассой эталона (`oracle/rr_oracle -ram A:B`) |

Таблицы и графику генератор читает из ROM пользователя (`rom/River_Raid.rom`), данных игры в коде нет.

## Как устроен генератор
Каждый вызов `nextLine()` выдаёт новую верхнюю строку экрана:
1. `structureAndWidth`: счёт строк (блок — 32 строки, участок — 2 блока, до моста — 16 участков), шаг LFSR, новая целевая ширина в начале участка;
2. `smoothIsland`: остров и ширина воды плавно идут к цели;
3. `moveBank`: случайное блуждание берега;
4. `startDecoration`: дом или гора на берегу;
5. `drawLine`: 48 байт строки (заливки, куски кромки из таблицы `$B800`, строка декорации);
6. `scrollObjects` / `placeObject`: слоты объектов сдвигаются, каждые 16 строк ставится новый объект.

От игрока и от `RANDOM` генерация не зависит. Это проверено на эталоне: разные сиды POKEY и прогон бота против полёта без управления дают одинаковое состояние на всех строках.

## Проверка
- От состояния из эталона: 119 758 строк всей реки (120 000 кадров), расхождений в состоянии и в растровых строках 0.
- С нуля (`startGame(1)` без эмулятора): после 165 строк заполнения экрана состояние совпадает с оригиналом, затем 29 757 строк без расхождений.
- Игра бота со взрывами мостов и миганием: расхождения только в кадрах возрождения. Их делает код рестарта, он пока не перенесён.
- Проверка ловит внесённые ошибки: каждая из четырёх намеренных поломок (условие блуждания, ширина воды, отрисовка, цвет заливки) дала расхождения.

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/ghost_film.txt 30001 out -ghost -ram 0:30000
port/build/terrain_check rom/River_Raid.rom out/ram.bin 0 240 29760 5 -fresh 1 145
```

Отрисовка: в каждом кадре, где в строку экрана 20 входит новая строка, строка оригинала сравнивается с `drawScreenLine()` для строки из генератора на C++ (запущенного с нуля).
- Объекты там, где их поставил генератор: 96,8% строк совпадают за 29 000 кадров (95,3% за 120 000). Остальные отличаются там, где игра сдвинула объект.
- Положения объектов из идущей игры (`-ram`: x, флаги, вид слота): совпадают 98,1%; все оставшиеся строки отличаются только пока активен танк на дороге (`$38`), его рисует логика игры. Необъяснённых строк из 29 600 — 0.

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/ghost_film.txt 30001 out -ghost -strip 20 -ram 0:30000
port/build/render_check rom/River_Raid.rom out/strip.bin out/frames.csv -ram out/ram.bin
```
Панель и бегущая строка: наборы символов, собранные из шрифта ОС и картриджа, равны RAM оригинала, состояние прокрутки ($3FB3/$26/$27) совпадает в каждом кадре, а нарисованные строки 180–239 совпадают во всех 1299 кадрах, кроме крайних столбцов бегущей строки (см. «Просмотрщик реки»).

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/attract_idle.txt 2300 out -screens 1000:2299 -ram 1000:2299
port/build/status_check rom/River_Raid.rom out/screens.bin out/ram.bin
```
