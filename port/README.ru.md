# C++ порт River Raid

[English](README.md) | Русский | [Українська](README.uk.md) | [Deutsch](README.de.md) | [Polski](README.pl.md) | [Italiano](README.it.md) | [Español](README.es.md) | [中文](README.zh.md) | [日本語](README.ja.md)

Неофициальный любительский проект в образовательных целях, не связан с Activision и Microsoft; частей игры в нём нет (см. оговорку в `../README.ru.md`).

Вся игра: `river_raid` играет в River Raid так же, как оригинал, — демо-режим, выбор игры, один и два игрока, самолёт, топливо, враги, мосты, очки, жизни, рекорды, пауза и звук. Генератор реки и логика игры дают покадрово то же состояние RAM, что оригинал, отрисовка — тот же экран (см. «Проверка»).

## Сборка
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```
Ядру и утилитам нужен только компилятор C++17. Игре `river_raid` и просмотрщику `river_view` нужен SDL3: если CMake находит установленный SDL3 (3.4 или новее), он берёт его, иначе при конфигурации скачивает SDL 3.4.20 с GitHub (нужны git и интернет) и линкует статически. Под Linux для сборки SDL из исходников нужны dev-пакеты X11/Wayland (см. `docs/README-linux.md` в SDL). Если такого пакета нет, SDL 3.4 останавливается с ошибкой и называет опцию, чтобы собраться без него (например, `-DSDL_X11_XCURSOR=OFF`). Совсем без SDL: `cmake -S . -B build -DRR_VIEWER=OFF`.

С SDL2 вместо SDL3 (для платформ, которые SDL3 больше не поддерживает, например UWP на Xbox): `cmake -S . -B build -DRR_SDL2=ON`. Тогда CMake берёт установленный SDL2 (2.0.18 или новее) или скачивает SDL 2.32.10. Программы обращаются к SDL только через `sdl/host.h`, у которого по реализации на каждую версию; картинка в обоих случаях одинаковая.

Под Windows с Visual Studio: `cmake --build build --config Release`, программы появятся в `build\Release\`. Собрано и проверено в игре под Windows (MSVC), macOS (Xcode, Apple M2) и Linux (gcc).

## Игра
```
river_raid [rom] [параметры]
```
Без аргументов сама находит ROM (см. `rom`) и запускается как картридж: демо-режим, потом START.

| Параметр | Что делает |
|---|---|
| `rom` | образ картриджа (8192 байта). По умолчанию ищется `rom/River_Raid.rom` в текущей папке и до трёх папок выше, так что из репозитория или из `port/build/Release` игра запускается без аргументов |
| `-os файл` | буквы и цифры из ОС самой Atari: образ ROM ОС (10 КБ или 16 КБ) или файл шрифта на 1 КБ. Без него — встроенный шрифт AltirraOS |
| `-seed N` | другая река, с другими врагами и заправками. N — состояние, с которого начинает генератор реки, от 1 до 16777215. Игра 1 начинается с начала этой реки, игры 3–8 — у её мостов 5, 20 и 50; уровень у каждой игры свой, как обычно, так что сложность растёт так же. Родная река картриджа — `-seed 16241891` |
| `-bridge N` | каждая игра (1–8) начинается у моста N, от 1 до 9999: с N на счётчике мостов и с уровнем этого моста (после 80 уровень чередуется 79/80, как в оригинале). Работает и вместе с `-seed`. Точка старта находится прогоном генератора реки до неё (меньше секунды даже для 9999) |
| `-random N` | начальное значение счётчика RANDOM микросхемы POKEY, от которого зависит, какой враг когда проснётся, и шум взрывов. По умолчанию берётся от часов, как у настоящей машины он зависит от момента включения, поэтому каждый запуск свой; с одним и тем же N запуск с теми же нажатиями повторяется точно |
| `-pal` | играть как машина PAL: как на настоящей PAL Atari, заправки становятся реже до уровня 47, а не 46; цвета PAL. Тайминги экрана остаются NTSC (см. «Ещё не сделано») |
| `-colours ntsc\|pal` | цвета машины NTSC или PAL; по умолчанию PAL. C переключает на ходу |
| `-palette altirra\|atari800` | модель цветов: `altirra` (по умолчанию) или `atari800` (темнее в средних тонах). V переключает на ходу |
| `-border` | показывает весь кадр с чёрной рамкой (384×240 без 10 столбцов по бокам), как эмуляторы. По умолчанию окно показывает только картинку игры со всей бегущей строкой, 364×200, поэтому на весь экран она примерно на 20% крупнее, а окно на столько же ниже. O переключает на ходу |
| `-filter sharp\|nearest\|linear` | как картинка масштабируется до окна или экрана: `sharp` (по умолчанию) увеличивает в целое число раз с чёткими пикселями, а потом плавно до нужного размера — картинка чёткая, и все пиксели одного размера; `nearest` — просто квадратики, но при нецелом масштабе (по горизонтали он нецелый всегда, пиксели Atari не квадратные) часть столбцов выходит на пиксель экрана шире; `linear` — плавно, размыто. L переключает на ходу |
| `-stats` | выводит рендерер и частоту экрана, потом раз в секунду частоту кадров, время на кадр и очередь звука |
| `-nosound` | без звука |

В заголовке окна видно, какие сейчас цвета и масштабирование. На экране 60 Гц (или 120 Гц...) игра идёт ровно с частотой экрана (60 кадров в секунду вместо 59,92 у Atari), чтобы каждый кадр показывался одинаково долго; на остальных экранах — с частотой Atari.

Примеры: `river_raid -bridge 30` — старт у моста 30; `river_raid -seed 12345` — другая река; `river_raid -seed 12345 -bridge 80` — эта река на максимальной сложности.

После включения над рекой летает демо-режим. START начинает игру; SELECT (или OPTION) выбирает игры 1–8: чётные — для двух игроков (ходят по очереди), игры 3–4, 5–6 и 7–8 начинаются с мостов 5, 20 и 50. Любая клавиша клавиатуры Atari — пауза. После конца игры экран стоит, пока снова не запустится демо-режим (около 35 с). Игра и просмотрщик закрываются обычным способом: закрыть окно, Alt+F4, Cmd+Q.

| Клавиша | Atari |
|---|---|
| стрелки или W A S D | джойстик: влево/вправо — поворот, вверх — быстрее, вниз — медленнее; любое направление выпускает самолёт у моста |
| левый/правый Ctrl, Z, X | огонь |
| F4 или Enter | START |
| F3 | SELECT |
| F2 | OPTION |
| Пробел | клавиша клавиатуры: пауза |
| F, F11 или Alt+Enter | полный экран |
| C | цвета NTSC / PAL |
| V | модель цветов Altirra / atari800 |
| O | только картинка игры / весь кадр с рамкой |
| L | масштабирование: sharp / nearest / linear |
| F7 / F8 | сохранить состояние игры / вернуться к нему (в памяти, до выхода) |
| Esc | выход из полного экрана |
| щелчок мышью | прячет указатель мыши, пока мышь не сдвинется (переход в полный экран тоже) |

Клавиатура управляет обоими джойстиками, так что и в игру на двоих можно играть одному. Геймпады: первый — джойстик 1 (и 2, пока второго нет), второй — джойстик 2; крестовина или левый стик, A/B/X/Y или правый курок — огонь, Start = START, Back = SELECT, LB / RB = F7 / F8 (сохранить состояние / вернуться к нему).

## Просмотрщик реки
```
river_view [rom] [параметры]
```
Показывает демонстрационный режим оригинала — пролёт над рекой, который игра крутит, пока никто не нажимает START: после включения экран заполняется рекой игры 1, дальше она прокручивается на 1 строку за кадр; корабли и вертолёты просыпаются и плавают, танки едут к мостам и стреляют, вертолёты пускают ракеты (перенесённая логика игры, `src/game.cpp`); внизу панель состояния и бегущая строка с титрами, «Press START key» и радужным логотипом Activision. Параметры те же, что у игры: `rom`, `-os`, `-seed`, `-bridge` (просмотрщик сначала долетает до него от начала реки, одной рекой, для 9999 это несколько секунд, и показывает его таким, каким он был бы в полёте; назад можно смотреть до самого начала), `-random`, `-pal`, `-colours`, `-palette`, `-border`, `-filter`.

Буквы и цифры 1–9 берутся из шрифта ОС, которого нет в картридже. В порт встроен шрифт AltirraOS — свободной замены ОС, которая идёт с atari800 (лицензия разрешает копирование и изменение при сохранении копирайта, см. `src/os_font.cpp`); с ней же сняты эталонные трассы. `-os файл` берёт шрифт ОС самой Atari из образа ROM ОС (10 КБ или 16 КБ) или из файла шрифта на 1 КБ.

| Клавиша | Действие |
|---|---|
| Пробел | пауза |
| Вверх / Вниз | быстрее / медленнее, через остановку до полёта назад (от x1/4 до x16 в обе стороны) |
| колесо мыши, PgUp / PgDn | прокрутка по реке вручную, на экран |
| Backspace | вернуться к самой новой строке, обычная скорость |
| B / Shift+B | следующий / предыдущий мост |
| Alt+B / Alt+Shift+B | на 10 мостов вперёд / назад |
| Ctrl+B / Ctrl+Shift+B | на 100 мостов вперёд / назад |
| Home | начать заново |
| F1 / F2 / F3 | проверка звука: взрыв / выстрел / звук очков через звуковой драйвер игры (сам демо-режим беззвучен, как в оригинале) |
| F | полный экран |
| C | цвета NTSC / PAL |
| V | модель цветов Altirra / atari800 |
| O | только картинка игры / весь кадр с рамкой |
| L | масштабирование: sharp / nearest / linear |
| Esc | выход из полного экрана |
| щелчок мышью | прячет указатель мыши, пока мышь не сдвинется (переход в полный экран тоже) |

Сравнение с экранами оригинала (демо-режим, кадры 1000–2300, со значениями RANDOM из оригинала): область реки и панель совпадают попиксельно, бегущая строка тоже, кроме крайних столбцов (левее 24 и правее 359), где эмулятор по-своему обрабатывает плавную прокрутку у края.

Какой объект когда просыпается, решает регистр RANDOM микросхемы POKEY — аппаратный счётчик, который читается в момент, зависящий от таймингов всей машины. Порт моделирует этот счётчик (`src/pokey_random.h`) и запускает его от часов, как настоящая машина запускает его при включении, поэтому каждый запуск свой, как и на настоящей машине; `-random N` повторяет запуск.

## Код
Порт написан так, чтобы его можно было читать без листинга оригинала под рукой:
- поля состояния, функции и константы названы по смыслу (`planeState`, `shellTimer`, `enteringSlot`, `positionObject`, `kFacingLeft`); в комментарии к каждому полю указан его адрес в RAM оригинала, у каждой функции — адреса кода, из которого она перенесена, так что листинг (`disasm/`) и трассы по-прежнему легко сопоставить;
- таблицы картриджа читаются через именованные функции в `src/rom.h` (`rom.points(type)`, `rom.objectHeight(type)`, `rom.shellRise(t)`...), а не по адресам;
- значения остаются 8-битными с переполнением там, где они такие у оригинала (`lo()`): координаты заворачиваются через край экрана; где оригинал переносит флаг переноса 6502 из одной суммы в следующую, это явно видно по `addWithCarry`/`subtractWithBorrow`;
- прерывание списка отображения (`display.cpp`) — единственная часть, оставшаяся близкой к командам: от того, где в строке развёртки они выполняются, зависит, какие столкновения видны, поэтому оно выполняется с подсчётом тактов.

Изменения, которые не должны менять поведение, проверяются `tools/equivalence`: он собирает более старый коммит (начиная с 06ffc73) рядом с рабочей копией и прогоняет обе версии на 150 000 строк реки каждой игры (NTSC и PAL), на случайной игре от включения и от 194 состояний из трасс оригинала, сравнивая после каждого шага всё состояние, экран и регистры звука. Так проверены переименование и перестройка генератора, игры и показа (0 отличий), а также всеми проверками ниже.

```
port/tools/equivalence/build.sh 06ffc73
port/build/eq/eq
```

## Как устроен генератор
Каждый вызов `nextLine()` выдаёт новую верхнюю строку экрана:
1. `countLines`: счёт строк (блок — 32 строки, участок — 2 блока, до моста — 16 участков), шаг LFSR, новая целевая ширина в начале участка (`chooseSectionWidth`: острова появляются и исчезают);
2. `changeIsland`: остров и ширина воды плавно идут к цели;
3. `moveBank`: случайное блуждание берега с разворотом у границ и перед новым объектом (`bankWouldHitObject`);
4. `startDecoration`: дом или гора на берегу;
5. `drawLine`: 48 байт строки (заливки, куски кромки из таблицы `$B800`, строка декорации);
6. `scrollObjects` / `placeObject`: слоты объектов сдвигаются, каждые 16 строк ставится новый объект (`chooseEnemy`, `positionObject`, `placeTank`).

От игрока и от `RANDOM` генерация не зависит. Это проверено на эталоне: разные сиды POKEY и прогон бота против полёта без управления дают одинаковое состояние на всех строках.

## Проверка
- От состояния из эталона: 119 758 строк всей реки (120 000 кадров), расхождений в состоянии и в растровых строках 0.
- С нуля (`startGame(1)` без эмулятора): после 165 строк заполнения экрана состояние совпадает с оригиналом, затем 29 757 строк без расхождений.
- Игра бота со взрывами мостов и миганием: расхождения только в кадрах возрождения. Их делает код рестарта, он пока не перенесён.
- Проверка ловит внесённые ошибки: каждая из четырёх намеренных поломок (условие блуждания, ширина воды, отрисовка, цвет заливки) дала расхождения.

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/ghost_film.txt 30001 out -ghost -ram 0:30000
port/build/terrain_check rom/River_Raid.rom out/ram.bin 0 240 29760 5 -fresh 1 145
```

Отрисовка: в каждом кадре, где в строку экрана 20 входит новая строка, строка оригинала сравнивается с `drawScreenLine()` для строки из генератора на C++ (запущенного с нуля).
- Объекты там, где их поставил генератор: 96,8% строк совпадают за 29 000 кадров (95,3% за 120 000). Остальные отличаются там, где игра сдвинула объект.
- Положения объектов из идущей игры (`-ram`: x, флаги, вид слота): совпадают 98,1%; все оставшиеся строки отличаются только пока активен танк на дороге (`$38`), его рисует логика игры. Необъяснённых строк из 29 600 — 0.

Игра с игроком (`game_check` на прогонах с вводом). Где результат оригинала зависит от тактов процессора:
- DLI (`display.cpp`) выполняется с подсчётом тактов, так же как эталонный эмулятор отсчитывает строку: в начале выборка спрайтов и списка отображения, процессор до такта 28, затем рисуется вся строка (со столкновениями), затем выборка экранных данных, WSYNC на такте 106. Поэтому известно, видит ли чтение регистра столкновений текущую строку: пуля, коснувшаяся объекта только на строке чтения, засчитывается на мосту (там чтение после такта 28) и не засчитывается в других местах — как у оригинала.
- Снимок RAM делается в конце кадра; обычно главный цикл оригинала в это время ждёт следующего кадра (AE99–AE9E). Сразу после старта игры, пока река заполняется по 2 строки за кадр, он иногда ещё дорисовывает вторую строку (1 кадр на заполнение). `game_check` показывает такие кадры отдельно и не сравнивает их; следующий кадр снова совпадает.
- Не смоделировано: конец игры. Логика главного цикла начинается на строке 160 и делит процессор с DLI и VBI (строка 248). В кадре конца игры проверка рекорда и его проверочных байтов (sub $B261, $B298) занимает тысячи тактов, поэтому `sub_B21A` ставит счётчик кадров в $FF перед VBI, после него или (игра на двоих) только в следующем кадре — смотря сколько тактов заняло всё, что было до неё в этом кадре. Порт делает это перед VBI; дальше счётчик кадров может отличаться на единицу, и следующий демо-режим сдвигается на кадр. Чтобы повторить это, нужен подсчёт тактов всего главного цикла в этом кадре (вместе с обработчиком прерываний ОС).

```
oracle/rr_oracle rom/River_Raid.rom oracle/scripts/start_only.txt 9000 out -bot -seed 3
port/build/game_check rom/River_Raid.rom out/ram.bin out/random.log 38 8950 -attract
```

Звук. Звуковой драйвер (VBI B2A5–B3D8, `Game::soundDriver`) прогнан на RAM, которая была у оригинала в начале каждого VBI в игре бота (2989 кадров, из них 2199 со звуком: мотор, предупреждение о топливе, взрывы, выстрелы, очки, снаряд танка): все значения AUDF/AUDC совпали с тем, что записал оригинал. Модель POKEY (`src/pokey_sound.cpp`) сравнена со звуком atari800 на тех же записях в регистры: та же громкость во времени (корреляция огибающих 0,95), те же чистые тоны на той же высоте, шум с той же формой спектра (косинус сглаженных спектров 0,94); посэмпловый рисунок шума отличается — он зависит от того, где окажутся шумовые счётчики.
